# Chat worktrees and branches

- Before investigating, reporting on, or changing this repository (including read-only work), inspect `git status` and `git worktree list`, then run `git fetch origin`. In the shared `~/Projects/atv-offroad-fury-2-web` checkout, confirm it is on `main`, clean, and not being changed by another agent, then run `git merge --ff-only origin/main`. Verify `git rev-parse HEAD` equals `git rev-parse origin/main` before using shared files as the current baseline. Refresh again when resuming after a pause or before an integration checkpoint; a previous fetch is not proof that main is current.

Never reset, stash, discard changes, switch branches, or force-update main to synchronize it. If fetching succeeded but synchronization is unsafe, investigate the fetched `origin/main` directly or use an isolated worktree and explicitly distinguish it from the stale shared checkout. Agents sharing this repository must serialize updates to shared main.

Create new worktrees as part of the authorized task without asking again. Read-only investigation may use the synchronized shared checkout.

# Rust only

- All game work goes into the Rust engine (`crates/atv-game`, `atv-render`, `atv-ui`, `atv-net`, `atv-content`, `atv-app`, plus `atv-core`), which builds the web game (`/play.html`) and the macOS, Windows and Linux desktop apps from one codebase. This covers features, enhancements, original-behavior fidelity fixes, UI, audio, multiplayer and performance work.
- The JavaScript game was retired on 2026-10-23, when `play.html` switched to the Rust engine (research/SWITCHOVER.md). Its modules, `web/worker.js` and `crates/atv-web` are gone from the tree. It survives only as a read-only parity reference: `python3 tools/js_reference.py prepare|serve|test` builds and serves the pinned last pre-switch main in ignored `work/js-reference`. Do not restore it, and do not port Rust work back to it.
- If a request names a former JavaScript file or "the web game", implement it in the Rust engine. Read the reference (`git show <pin>:web/<file>`) or run it in comparisons (`ATV_JS_URL`, read by `compare_engine.mjs`, `compare_audio.mjs` and the JavaScript guests in relay tests) only to establish the previous behavior.
- The page shell is not game code and stays JavaScript: `web/engine.js` (the Wasm loader), `sw.js`, `install.js`, `offline.js`, `analytics.js`, `devlog.js` and `landing.js`. Keep it minimal; put game logic in Rust.
- Browser tests target `/play.html` (`tools/test_engine_*.mjs`). `/engine.html` is the same page under its pre-switch name (written by `tools/build_engine.py`); keep it working for old links but do not target it in new tests.

## Deployment goes through GitHub Actions

- Ship small and often. When a change is tested, merge current `origin/main` into the task branch, resolve conflicts, rerun only the focused checks the conflict touched, push, then `gh pr create` and `gh pr merge --auto --merge --delete-branch`. Do not ask again and do not wait: the required `web` check gates the merge and the deploy follows automatically. Keep working; confirm `https://furyremastered.com/deployment.json` once at the end of the task.
- Do not push to `main` directly. If PR CI fails, fix it on the branch; the queued auto-merge stays armed. A merge conflict after queuing is fixed the same way.
- Test once, focused: run the content browser tests that cover what changed, once, at handoff. CI already runs `make check`, the build and the content-free smoke group on every PR, so do not repeat those as a separate local gate unless debugging, and do not rerun checks another chat already ran on the same commit. Full browser matrices are for explicit acceptance passes only.
- Keep branches short-lived and merge `origin/main` in at each checkpoint so conflicts stay small. Browser tests use `tools/browser/harness.mjs` and must be listed in `tools/browser/manifest.mjs`.
- A newer push cancels an older PR build. Main builds run to completion and each deploys if it advances production, so the site keeps up while merges land quickly; deploys run one at a time, are never interrupted, and never replace a newer release. If the latest main run fails, fix forward or rerun its failed jobs (`gh run rerun <run-id> --failed`).
- `tools/deploy_local.py` cancels main runs and deploys from the host. Use it only when the user explicitly asks for a local deployment in the current conversation, passing `--user-requested`. It keeps the clean-checkout, allowlist, lock, R2 and public verification guards described in `research/CI_CHECKPOINTS.md`. No Mistakes remains disabled; the experimental release queue was removed.
